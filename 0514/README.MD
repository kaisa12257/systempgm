1. 네트워크 핵심 장치 및 주소 조회
라우터 (Router): 서로 다른 두 개 이상의 네트워크를 연결하며, 데이터 패킷의 목적지 주소를 기반으로 최적의 경로(Routing)를 설정해 전송하는 장치입니다.
게이트웨이 (Gateway): LAN 내부망을 더 넓은 외부 인터넷망으로 연결해 주는 출입구 역할을 하는 컴퓨터나 장치(고용량 라우터 등)를 의미합니다.
HTTP: 웹 서버와 클라이언트(브라우저) 간에 텍스트 및 멀티미디어 데이터를 주고받기 위한 기본 애플리케이션 프로토콜입니다.
주요 조회 명령어:
hostname : 현재 사용 중인 시스템의 호스트 이름 출력
ip addr : 시스템에 할당된 네트워크 IP 주소 정보 출력
nslookup 호스트명 : DNS 서버를 통해 도메인의 IP 주소를 추적 및 확인
finger 사용자명 : 특정 사용자의 로그인 정보 및 상세 프로필 조회
2. 발표 주제 및 웹 서버 스택
와이어샤크 (Wireshark): 네트워크 패킷을 실시간으로 캡처하여 프로토콜 단위로 정밀 분석하는 가장 대표적인 오픈소스 패키지 스니핑 툴입니다.
CasaOS: 리눅스 기반 환경에서 도커(Docker) 컨테이너 및 홈 서버 앱들을 GUI 환경으로 쉽게 관리할 수 있게 해주는 개인용 클라우드 OS 레이어입니다.
APM 스택 (웹 서비스 삼총사):
A (Apache): 가장 널리 쓰이는 웹 서버 (우분투 패키지명 apache2, CentOS 패키지명 httpd)
P (PHP): 동적 웹 페이지를 생성하는 서버 사이드 스크립트 언어
M (MariaDB): 대용량 데이터를 저장하고 PHP와 연동하여 서비스하는 관계형 데이터베이스
3. 파일 및 레코드 잠금 (Locking) 원리
동시성 문제: 여러 프로세스가 단일 파일에 동시에 접근하여 쓰거나(Race Condition), 한 프로세스가 수정 중인 파일을 다른 프로세스가 읽을 때 데이터 왜곡이 발생합니다.
해결책 (잠금): 쓰기/수정 작업 시 특정 영역을 잠가(Lock) 한 번에 하나의 프로세스만 접근하도록 제어합니다.
파일 잠금 (flock): 파일 전체를 대상으로 잠금을 수행합니다.
LOCK_SH (공유 잠금): 읽기 작업 시 사용하며, 여러 프로세스가 동시에 공유 잠금을 걸고 읽을 수 있으나 쓰기는 차단됩니다.
LOCK_EX (배타 잠금): 쓰기 작업 시 사용하며, 다른 프로세스의 읽기와 쓰기를 모두 완벽히 차단합니다.
레코드 잠금 (fcntl): 파일 전체가 아닌, 파일 내부의 특정 바이트 범위(레코드)만 정밀하게 잠그는 제어 방식입니다.
4. 권고 잠금 (Advisory) vs 강제 잠금 (Mandatory)
권고 잠금: 커널이 차단하지 않고 프로그램들끼리 서로 규칙을 지키기로 약속하는 방식입니다. 잠금 규칙을 무시하는 프로세스가 강제로 읽고 쓸 수 있으므로, 협력하는 모든 프로세스가 자발적으로 잠금 코드를 준수해야 합니다. (Linux, BSD, Mac OS 표준)
강제 잠금: 커널이 직접 개입하여 잠겨 있는 영역에 대한 타 프로세스의 읽기/쓰기 시도를 원천 차단합니다. 보안성이 높으나 시스템 부하가 증가합니다. (System V, Solaris 계열 표준)
리눅스에서 강제 잠금을 적용하는 조건:
파일 시스템 마운트 시 -o mand 옵션을 명시해야 합니다.
대상 파일의 실행 권한 중 SetGID 비트를 켜고(2000), 그룹 실행(Group Execute) 비트를 꺼야 커널이 강제 잠금 파일로 인식합니다.
